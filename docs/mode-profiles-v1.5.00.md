# v1.5.00：独立模式参数、默认值与单图对比

六种选择仍是六条投影/边缘处理路线，共用原有稳定深度模型；不是六份下载模型。算法区别保留在 [v1.4.00 模式说明](mode-comparison-v1.4.00.md)。本版按用户偏好把 V10、V6 放在设置选项前面，不据此声称客观画质排名。

## 每个模式的参数与默认值

每个模式独立保存强度、滤波、填充、模型输入反转、投影反转、输出长边和深度放大设置。切换时自动保存旧模式、恢复新模式。模型选择、GPU、线程、worker 和来源队列设置仍为通用项；切换视觉模式不会关闭强制 GPU。

- **保存为默认值**：把当前模式的视觉参数保存为该模式的个人默认；显式等待磁盘提交，失败显示错误。
- **恢复此模式默认值**：恢复这份个人默认；尚未保存时使用内置默认。
- **恢复内置默认**：清除当前模式的个人默认并恢复内置值，其他模式保留。

首次迁移保留升级前正在使用的参数。其他尚未使用的模式自动使用内置默认；已保存的自定参数不会因升级被悄悄改成 50。需要切回本版基准时使用“恢复内置默认”。`REFERENCE_V8` 的历史偏好迁移仅在首次接管时执行；新模式档案允许显式选择 V8 并在重启后保持，已持久化的 V8 任务仍按原版本续跑。

## 内置默认以 V10 深度 50 为基准

这不是需要手动套用的“对照预设”。内置默认生成时会根据当前图的实际眼宽、深度分布自动换算其他模式的原生强度。V10/V11 为 50，额外深度放大关闭、窗口 3。V6/V7 及 External 的实际数值随图像变化，记录在结果参数和调试页。

V10 位移单位约为 `255 × d × s / w`；External 为 `w × d × s / 500`。仅按宽度换算，或按 V6 3×3 内部增益 4/9 乘以 9/4，仍不足以匹配：V10 双三次恢复后的归一化会改变深度对比度。

因此本版在保持各模式原有深度处理和投影实现的前提下，以相同原始深度、相同实际尺寸重建 V10 默认深度，计算 P90−P10 的跨度，再换算投影强度。平坦/无效深度采用有界回退，External 保持原生 0–100 的限制。整数取整、边界覆盖、静态眼、绝对会聚和遮挡填充仍不同，不能把一个跨度对齐说成整个立体画面完全等价。

三张指定人像与作者 README 示例预览裁片的 Android GPU 对照共 8 组尺寸：单纯公式换算相差约 10%–24%；按图校准后的首轮最大浮点跨度相对差约 **0.17%**，最终源码复跑为 **0.085%**。这是参数幅度指标，不是画质分数、轮廓误差或平行眼舒适度评分。原图和对照图片只保存在 `.local/iteration-1.5.00/`。

自动默认在缓存键追加 `_eq1050`。手动自定强度后使用该模式原生单位，并退出自动匹配；保存默认值也保留这个选择。旧缓存键在新标志关闭时保持兼容；小数强度使用自身精度标识，避免 112 与 112.5 冲突。

## 模型深度和投影深度的方向

本轮查看了三张人像及官方预览裁片的原始稳定模型输出：近处物体比远处亮，模型深度为近白远黑。脸比更近的衣袖暗不等于方向错误。

模型输入反转与各投影的反转分别保存：前者用于模型输出极性相反时，在进入模式处理前执行一次；后者沿用历史算法/眼序约定。内置默认的输入反转关闭；V6/V7 投影反转关闭，V10/V11 开启。External 的静态眼与 V10 相反，默认投影反转开启，因此其投影深度可以近黑，同时保持相对近远的视差方向。

不能为了让某张投影诊断图“人物全白”而盲目重复反转。设置中分别命名两个开关；六模式对比可切换 **SBS / 模型深度 / 投影深度**。新结果另存 `model_depth.png`，原 `depth.png` 保留实际模式处理后的深度；历史结果没有模型深度文件时显示暂无，不自动重算。所有 PNG 均只作诊断，投影继续使用浮点深度。输入反转开启追加 `_di1` 缓存标识，视频队列同时持久化两个开关。

## 单张图片的六模式临时对比

从 Viewer 的“调试”按钮或长按文件名进入，点击“六模式临时对比”。只读取当前原图，共享一次同设置的原始推理，使用各自已存参数；也可按各模式默认重新生成临时对比。参数不会因此写回设置，结果不会进入成品库、MediaStore 或来源队列。

六组结果预先解码驻留，按钮只切换图像引用，无图片切换动画或磁盘加载过渡。手势状态以对比会话为 key，不以模式、结果路径或创建时间为 key；下方显示实际缩放和位置。双击复位。关闭/杀进程后临时对比释放，不留下持久任务。

同一轮使用共同实际尺寸，预览和六组输出受内存预算约束。设置为 1920 不代表实际已经输出 1920；本轮平板对比的部分 1920 请求实际仅约 1100–1200 长边，官方裁片本身只有 560×836。提高上限可能保留更多输入像素，但不能增加 518×518 模型预测细节，也不能把位移随宽度变化造成的“更弱、更干净”误判成算法修复。

## 替换旧结果与另存新结果

图片操作明确区分：

- **使用新参数生成**：所有旧结果保留。相同目标参数已经存在时创建带 `_take…` 标识的新槽位，避免覆盖历史；相册标题显示副本编号。
- **重新生成**：成功后只替换当前查看或选中的旧结果，其他历史版本和原图保留。同一原图的多个所选版本去重为一次生成；目标参数对应的未选中历史结果同样保留。失败保留旧结果。

请求捕获具体版本和创建时间，随图片队列保存参数快照与写入意图。删除仍先使 GenerationGuard token 失效；新结果完整写入扫描范围外 staging，只有当前 token 才能提交。替换采用文件事务，先保留旧结果、提交新目录，之后才清理旧副本和更新索引。

事务 journal、提交标记及备份位于应用 `image_work`，不属于成品扫描范围；启动先恢复再扫描缓存。未提交的中断恢复旧结果，已提交的中断保留新结果并清理备份。恢复校验路径严格限制在本应用工作目录和缓存目录，冲突保留双方并记日志。旧队列字段缺失时保持原兼容语义，不把失败/用户暂停任务全局复活。

本版以上替换保证针对图片。视频仍走原有明确的清理并重做动作，确认文字单独说明，不借用图片的失败保留承诺。

## 界面与验收依据

Viewer 顶栏改为单行：长文件名省略，返回、VR 和可读“调试”入口保持同一行。按住顶栏期间不自动隐藏；调试和对比页的深浅文字颜色、两列深度预览、模式按钮及大字体布局一并整理。平板未改成手机尺寸/密度。

本版新增模式档案、标量校准、深度方向、选择替换与中断恢复测试，当前共 **116 项 JVM 测试**。严格真机对比等待实际图片视口出现，再检查缩放值 >1；不再用加载动画造成的哈希差当作缩放通过。实际结果、APK 哈希及发布检查见 [发布验收](releases/v1.5.00.md)，构建与真机分开记录。主体测试使用原尺寸平板；手机在用户重新授权连接后参与覆盖安装检查，未完成本版全套画质与手势复跑。私人素材不上传。
