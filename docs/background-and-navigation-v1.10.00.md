# v1.10.00：切页、批量任务与后台运行

本版处理冷启动后首次打开设置的卡顿、设置和生成页不能横滑、视频多选缺少开始/暂停，以及后台队列保护范围不足。模型、六种投影算法、精度、输出尺寸、JPEG 100 预览和原图无损 PNG 保存规则不变。

## 页面与冷启动

- 移除整页网格与新页面同时缩放/淡入淡出的切换，设置标题和四个分区固定，分区内卡片使用 LazyColumn；进入设置时不再先组合所有卡片。
- 设置四页、生成页图片/视频使用真实 HorizontalPager。点击标签立即跳转，滑动结束同步标签；各页保留自己的滚动位置。多选期间暂停横向切页，避免滑动选取与换页冲突。
- 标签等分可用宽度，可换两行，提供选中语义。保持原生设备比例，不通过改变平板分辨率冒充手机适配。
- 图片会话预热延后至首次布局之后，只在可见、加载完成、未开设置/管理/Viewer、非生成页且没有活动任务的图库执行。只准备已下载的当前图片模型，不下载、不测试推理、不创建队列。退到后台 30 秒后释放空闲会话，借用中的资源不关闭，释放仍在 GPU 拥有者线程。
- 加载完成必须等首次队列恢复结束；修复“刚开始的新任务又被恢复标签改成暂停”的竞态。

## 视频操作范围与参数

视频列表提供全部开始/全部暂停，数量只统计当前列表可操作项。多选提供开始所选/暂停所选及对应数量。开始跳过已完成、排队和运行中的项；显式开始可续跑暂停项或重试失败项。暂停只处理排队和运行项，不删除帧、结果或原视频。

续跑读取该任务保存的参数快照，优先于当前设置；排队暂停要在移除 job 之前捕获快照。用户修改设置后续跑，不会偷换为新参数。“重新生成”仍是明确清理并使用当前参数重做的独立操作，需要确认。

模型准备、进度及完成回调均须核验捕获的运行 token，发布状态与暂停/失效操作使用同一短临界区。暂停后晚到的模型回调不能再把状态写成 GENERATING。原生推理仍在拥有者线程完成，不强行中断；失效结果不发布。

## 后台运行与恢复边界

工作状态改由 Application 生命周期的单一 GalleryRuntime 持有，Activity 结束不再销毁队列拥有者。图片工人和原图 PNG 导出持有运行期前台服务租约；视频持有整批队列租约，不再每片结束停止、下一片在后台重新请求服务。多个消费者共享唤醒锁与服务，旧工人的释放不能停止新一轮任务。

API 35+ 使用 mediaProcessing 类型，较旧系统使用 dataSync；前台服务启动被拒绝必须显式暂停并提示，不能吞掉异常后继续无保护运行。系统时限回调保存/暂停并停止服务。遵守 [Android 前台服务时限](https://developer.android.com/develop/background-work/services/fgs/timeout) 与 [服务类型规则](https://developer.android.com/develop/background-work/services/fgs/service-types)，不更换类型规避限制。

扫描范围外 queue_index/background_run.txt 只记录用户明确开始的视频 key。服务收到系统 null Intent 重建时，才允许恢复记录中、仍为 QUEUED/GENERATING 且具有参数快照的任务。用户暂停、失败、完成、删除、历史项不自动复活；普通界面冷启动仍先暂停待用户续跑。15 分钟内最多自动尝试 3 次，防止原生崩溃循环。图片来源/窗口暂停、当前图片优先和预加载范围保持原规则，不借后台恢复扩大来源。

视频队列 TSV 保持旧字段顺序，追加可选 pauseReason；图片队列在替换意图后追加可选原因，旧记录仍可读。新增原因 USER、SERVICE_UNAVAILABLE、SYSTEM_LIMIT、PROCESS_RESTART 与原有来源/窗口暂停区分。原设置、历史版本、缓存标识与媒体持久化保持。

Android 与厂商清理不能由应用保证绕过。[用户停止前台服务](https://developer.android.com/develop/background-work/services/fgs/handle-user-stopping)、强行停止、重启及厂商最近任务清理仍会终止进程。此次平板 SIGKILL 后 35 秒内没有自动重启 sticky 服务；不能宣称“已解决所有后台被杀”。显式重建同一路径只验证了保存的准入范围和参数恢复，不冒充系统自动重启成功。设置增加当前电池优化状态、续跑说明及系统应用设置入口；部分厂商还需要用户锁定最近任务。
