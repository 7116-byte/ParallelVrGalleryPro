# v1.4.00：实际 ComfyUI 主节点对照与亚像素投影

版本 1.4.00 / 10400，新增可选模式，按“新增功能位”升级。没有迁移用户现有模式、重算旧结果或更换模型、签名与依赖。

## 为什么继续修正

用户指出本机 ComfyUI 在强度 60 时也比手机的参考模式干净。读取其真实执行历史后确认，实际使用的是 `SBS_V2_by_SamSeen` 主节点、HighSodium 关闭的 Legacy 路径，参数为窗口 3、反转开启、Parallel、Depth Anything V2 Small。此前 v1.3.00/01 对照的是 External Depth V2.2；二者不等价。

本机插件基线与核验时上游 main 一致，为 `30372fec69a1929ce6eb5fded8d23ba2604fd68f`；本机还存在缓存优先加载与 Legacy 向量化的未提交改动，保留不动。参考 [主节点源码](https://github.com/SamSeenX/ComfyUI_SSStereoscope/blob/30372fec69a1929ce6eb5fded8d23ba2604fd68f/sbs_v2.py) 和 [深度预处理](https://github.com/SamSeenX/ComfyUI_SSStereoscope/blob/30372fec69a1929ce6eb5fded8d23ba2604fd68f/depth_estimator.py)。

实际工作流单眼 1280×1920，PC 保持比例预处理为 518×784；手机稳定模型仍为 518×518。主节点强度使用 `depth8 × scale / eyeWidth`，与 External 的相对图宽单位不同；但不能只凭位移或分辨率解释所有轮廓异常。

## 两条独立的新模式

| 模式 | 缓存标识 | 行为 |
| --- | --- | --- |
| ComfyUI 主节点 · 原样兼容 | depthSSSMainV10 | 左眼投影、右眼原图；8 位深度量化、从左到右覆盖、位移 + 10 像素填充 |
| ComfyUI 主节点 · 亚像素 | depthSSSMainV11 | 保持主节点眼序和强度单位；浮点位移、深度分层与像素覆盖率混合，显露背景从较远相邻表面补齐；不使用 Telea |

两者均先将已有浮点深度以半像素几何的双三次插值恢复到实际眼图尺寸，重新归一化，再按窗口做 Gaussian。反转复选框沿用桌面主节点的含义，包含桌面估计器自身反转的约定；当前工作流应开启。固定执行用户所选窗口，不复刻上游首次加载可能误用默认 15、后续才应用 3 的状态差异。OpenCV 与 PyTorch 数值实现仍可能存在微小差异，不宣称整条桌面推理完全相同。

原样兼容仍可能有台阶和拉伸。亚像素只在投影覆盖边界混合，不对原图或整幅结果做模糊。它是本项目新增的改良，不称为插件官方新版本；有额外 CPU 开销，不能保证复杂遮挡完全正确或所有素材更优。

设置中新增明确的“60 / 3 / 反转”对照预设，同时关闭额外深度放大；点击前说明范围，GPU、输出尺寸及其他设置保留。切模式不自动重生成。原 V6/V7、V8/V9 及其缓存、已持久化任务保持原路径。旧滤波顺序偏好保留；主节点明确在最终眼图上执行 Gaussian，不显示不适用的旧顺序选项。可选额外重采样的参数和 `_du1_...` 标识仍独立持久化。

## 手机和 PC 的实际比较

仅用用户已指定三张人像和此前作者工作流截图输入裁片。没有把用户新生成的其他 ComfyUI 图片加入手机测试，也没有上传任何图片。官方裁片仍只是 560×836 预览，不是原始高清摄影图。

- 手机 2410DPN6CC 以原稳定模型、ACCURATE_UNSET、强制 GPU 产生深度。日志确认 delegateActive=true、无 CPU 回退。直接读写 `PVG_QA_comfy_1400` 专属目录，不经过 MediaStore、GalleryViewModel 或预加载队列。
- 四个输入各测 Legacy 40 / 60，共八组；用同一份手机深度注入本机真实主节点的推理输出入口后，手机与 PC 的投影 RGB **逐像素一致**。这仅证明主节点投影实现，未把注入深度的验证冒充完整 PC 推理。
- 另用本机已缓存的真实 PyTorch Small 模型，在同一份手机导出的标准 sRGB 像素上推理。四组归一化深度平均绝对差约 0.0049–0.0226，相关系数约 0.9969–0.9995。该相关系数不是主观画质分数，也不能证明所有素材都没有模型误差。
- 对照包含 External V9 在接近理论最大位移下的输出、手机 Legacy 40 / 60、手机亚像素 40 / 60、真实 PC 深度的 Legacy 输出。实际查看手臂、腰、头发及官方摩托车裁片。Legacy 在这些相同输入上也有台阶；亚像素减少了指定人像的台阶及部分补洞虚边，官方低分辨率裁片仍有明显遮挡缺陷。
- 单次暖态 P3 1280×1280 记录：GPU 推理约 347ms，Legacy 60 投影约 124ms，亚像素 60 约 425ms；不含全部解码、JPEG 写入或交互时间，不作为整机提速/FPS 结论。
- 实际 `VrGenerator.generateSbsBitmap` 产出的 P3 左眼与已测试的直接 renderer 完全相同，两个模式各 0 个不同像素。实际视频帧入口各处理三个合成帧，包含时间平滑；未把它写成完整长视频封装、PTS 或音画同步验收。
- 手机新增模式的七项 UI 状态检查通过：选择菜单、兼容设置、实际预设值、亚像素设置、深色大字体、滚动到参数以及大字体横屏；截图另行查看。原图、成品缓存不参与保存、重做或删除测试。

私人证据只存 `.local/iteration-1.4.00/`，包含 `desktop-phone-comparison-private.json`、`phone-native/report.json`、`phone-pipeline-report.json`、`phone-new-mode-ui-private.json` 和标注对照图。对照图复制原结果像素，不做修饰；设备上的 QA 输出在验收完成后仅按专属目录清理。

## 保持与限制

八个原核心区域仍与恢复基线逐字一致（归一化换行后）：队列与暂停、来源优先级、GenerationGuard 删除发布、模型/GPU 线程、视频有界流水线及单源双眼交互均未改。新模式额外缓冲使用自己的内存预算，旧模型输入仍为 518×518。

构建结果、最终包哈希、CI、覆盖安装和公开下载以 [发布验收](releases/v1.4.00.md) 的本次证据为准。16 KB 原生库、长期热降频、复杂遮挡重建、主观佩戴与完整长视频压力场景仍待单独验证；旧备份及普通版资产保留。
