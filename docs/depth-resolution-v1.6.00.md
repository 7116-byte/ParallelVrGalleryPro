# v1.6.00：固定透明顶栏与真实 770 深度推理

图库顶部操作栏固定，不再因滚动移出；背景透明，图片可以从其下方滚过。删除 v1.5.02 增加的底部设置按钮，底部只保留原导航或当前多选操作。调试直达设置及返回位置保留。

## 770 的来源与复现

设置 → 深度与输出 → 图片模型推理分辨率，可选择原稳定 518 或新的 770 图片模型。原偏好不迁移，原稳定模型不覆盖；视频仍只提供原来的 518 模型。推理模型为六种投影模式共用，与各模式独立视觉参数不同。

这次 770 是真正的 `[1,770,770,3]` 输入和 `[1,770,770,1]` 深度输出，不是对 518 深度图插值。Depth Anything V2 的特征 patch 为 14；770=55×14，是接近且高于 768 的合法尺寸。上游可变输入和位置编码见 [官方 DPT](https://github.com/DepthAnything/Depth-Anything-V2/blob/main/depth_anything_v2/dpt.py) 与 [官方 DINOv2 实现](https://github.com/DepthAnything/Depth-Anything-V2/blob/main/depth_anything_v2/dinov2.py)。

现有 518 TFLite 图固定了空间形状，直接 resizeInput 在 reshape 失败。本版通过 `tools/export_depth_770.py` 生成独立固定图：patch 网格 37→55、token 数 1370→3026、解码空间常量对应调整，位置编码按上游 bicubic / 0.1 offset 插值。其余权重不改、598 个算子不改；不是重新训练，也不是官方发布的 770 文件。原模型 SHA-256 必须匹配后才允许转换，导出目标已存在时拒绝覆盖。

复现使用 PyTorch 2.13.0、FlatBuffers 25.12.19、TensorFlow 2.20 的 schema、NumPy；这些只在本机研究工具环境中安装，不升级 Android 应用依赖。脚本显式接受 `--input`、`--output`、`--schema`，输出转换清单。正式模型重新导出后字节哈希一致。

## 真正执行的验证

三张授权人像和官方 README 预览裁片共四张，同一 RGB 张量比较：

- 电脑 TFLite 518/770 都真实执行，输出尺寸、有限值及非恒定深度检查通过。
- 与缓存的官方 Transformers Small 权重执行结果比较，770 的归一化 MAE 为 0.00028–0.00064，相关系数 0.999996–0.999999。518 对照也通过。该数值验证转换一致性，不是画质分数。
- 平板原生 GPU 518/770 均运行四张，日志确认各 598/598 算子交给同一个 GPU delegate 分区，没有 CPU fallback。GPU 与 CPU 归一化 MAE 小于 0.000002。
- 平板 518 首次准备 3.7 秒、单图 242–246 ms；770 首次准备 21.4 秒、单图 962–978 ms。仅指这台平板、本次独立会话，不承诺手机相同速度。770 空间像素约 2.21 倍、attention token 对约 4.88 倍，不是零成本增加。
- 再通过应用真实 DepthModelSession 和六种投影，4 张×2 尺寸×6 模式共 48 份眼图完成；GPU 创建、推理、释放仍使用原拥有者线程。诊断图按实际深度尺寸生成，图像后处理不再硬编码 518。

实际深度图中部分手部/发饰轮廓细化，人物局部深度及背景也可能变化。相同 V10/50 的人物轮廓对照仍可见取整/补洞毛边；高分辨率不是通用边缘修复，没有人体真实深度真值或全面主观画质排名。正式版本继续保留 518 默认和全部六种模式。

## 兼容边界

770 使用独立模型 ID，因此新结果自然进入独立缓存版本；旧模型 ID、旧结果和已持久化任务保持。选择模型不批量重算旧媒体，启动只准备已经下载的当前模型，不偷偷下载或推理。原来源队列、暂停原因、GenerationGuard、强制 GPU、单源 SBS 视频、视觉参数与深度放大规则不改。

新 JVM 测试检查输入输出契约、不允许“770 输入配 518 输出”、真实浮点网格保留、模型切换的缓存隔离以及视频参数不变。私密研究目录沿用最初 UI 修复工作编号 `.local/iteration-1.5.03/`，最终版本为 1.6.00；完整构建和设备结果见 [发布验收](releases/v1.6.00.md)。
