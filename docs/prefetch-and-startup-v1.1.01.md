# v1.1.01: 来源预加载、模型初始化与进度显示

## 预加载回归原因

v1.1.00 的 `deletedImagePrefetchKeys` 将被删除的图片 key 持久化为自动预加载禁用项。重新打开当前图只解除当前 key，前后邻图仍被排除，因此批量删过缓存后会退化成看一张生成一张。

本版移除此黑名单及读写 API，启动时仅清理该旧偏好字段，不重置其他设置。`GenerationGuard` 仍在删除时推进任务修订 token，旧任务的进度、文件提交和 READY 回调均不能重新生效。未来正常来源浏览可取得新 token，不永久禁止原图再次生成。

队列边界仍由页面和来源决定，而不是由删除名单决定：

1. 全部页/相册普通图片 Viewer 才能扩展该次捕获范围内的预加载；当前图实际启动后才放邻图进入流水线，当前图已缓存时无需等待。
2. 原 2/4/8 档位规划、相册范围、视频不参与图片预加载、单张运行中不强行中断等逻辑不变。
3. 进入生成页、打开生成结果、左右浏览，不新增普通预加载。只完成已有任务，或恢复已有的来源切换暂停任务；窗口外暂停、用户暂停和历史暂停不全局复活。
4. 明确点击“重新生成”仍允许新建所选任务，但不会开启邻图预加载。
5. 退出普通 Viewer 后，已有任务可完成，但不再扩展预加载窗口。
6. 删除取消所选对象的已有任务并失效旧结果。留在生成页时不会因浏览重新加入被删项；之后在全部/相册正常浏览原图，按新窗口重新生成是允许的。

日志新增 `image prefetch-window`，包含来源、相册、范围大小、档位和本次候选数。它与 `new-prefetch`（新任务）、`resume-source`（旧任务）分开，便于真机判断是否越界。

## 模型启动初始化

- ViewModel 启动后在后台准备已下载的当前图片模型，执行 SHA-256 校验、解释器/GPU delegate 创建和 `allocateTensors()`。
- 复用原 `IdleResourcePool` 和 `AffinityWorker`，创建、使用、释放仍在同一原生线程；不增加第二套图片推理会话。
- 只有模型 ID、线程数、GPU 开关/模式、强制 GPU 设置变化才重新选择会话；深度强度、滤波等视觉参数变化不触发初始化。
- 初始化失败的会话会关闭且不入池，后续明确生成可重试；设置页和日志显示初始化结果。
- 不自动下载模型、不预热所有模型、不运行虚构图片推理、不新增队列。视频的专用会话本版未改。
- `allocateTensors()` 并不等于已经执行首次推理；设备首次推理仍可能存在后端初始化开销。本版没有实测手机启动/首图提速幅度。

接口依据：[InterpreterApi.allocateTensors](https://developers.google.cn/edge/api/tflite/java/org/tensorflow/lite/InterpreterApi)；[GPU delegate 线程要求](https://developers.google.com/edge/litert/android/gpu)。

## 深度滤波与插值不是同一个参数

当前实现先产生 518×518 的归一化深度，再在同样大小的网格上做滤波。立体投影通过整数坐标读取小图深度，没有先放大成原图尺寸的浮点深度图。

- 新版居中模式的 `3` 表示 3×3 邻域均值，`5` 表示 5×5；横向、纵向两遍实现一个二维均值窗口，不是重复插值的次数。
- 旧版保留历史非对称取样及幅度行为，同一数值不与新版等效。
- `0/1` 均不做滤波。
- 滤波意图是抑制局部深度噪点，代价是可能混合前景/背景深度，影响轮廓。它不增加深度分辨率，也不恢复真实细节。
- 本版只改名称与说明，不改滤波、投影、眼序、缓存版本，也未引入全分辨率插值。

## 视频完成进度

缓存可在重启后恢复，但 `videoJobs` 是有限的内存记录。之前缺少 job 时，界面把空进度当 0，导致已生成视频显示 0%。

统一显示规则：READY 为 100%；GENERATING 在文件完成前最多 99%；其他状态保留有效进度。未知帧总数不显示虚假的 0/0，READY 已知总数时显示总数/总数。不改视频生成和播放算法。
