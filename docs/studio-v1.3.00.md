# v1.3.00：统一创作界面与参考新版投影

版本：1.3.00 / 10300。应用 ID 仍为 `com.local.parallelvrgallerypro`，源码目录沿用 `com/local/parallelvrgallery`。恢复基线及旧备份保管规则仍见恢复验收记录，本次正式迭代不删除备份。

## 界面规范与覆盖范围

`StudioTheme.kt` 定义统一的浅色/深色语义色、圆角和内容容器。外观跟随系统；内容区使用 background / surface / onSurface，图片上的遮罩和沉浸式 Viewer 单独保持深色。系统栏图标随主题改变。设置和诊断页面自然滚动，不固定占用一块标题区域。

- 全部/相册：紧凑标题、图标操作、明确使用指南，标题与通知一起随列表移出；移除 104/128dp 固定预留。照片补充文件名和状态的无障碍语义。
- 生成：图片/视频切换、可读的参数版本名称、独立空状态。视频任务有文件名、帧数/百分比、进度条及错误，未知帧数不伪造。内容不足一屏时隐藏滚动条。
- 多选：底部圆角操作槽显示当前列表范围、全选、保存副本、重生成、删除结果。实测操作槽高度用于列表底部留位，支持大字体换行，最后一项可以滚到操作槽之上。生成相册原有去重与版本范围不变。
- 修复生成网格长按松手后又触发缩略图点击、立即取消选中的问题。选择手势观察长按/拖动后接管静止移动及抬手；滚动和双指缩列可取消尚未成立的长按。视频文件名和进度区也可点击进入 Viewer。
- Viewer：统一深色控件、可收起操作栏；不再强制原图模式一直显示控件。保留单播放器、同眼内坐标和同步手势。视频活跃页还需处于前台生命周期，返回桌面时暂停播放，不改变后台生成队列。
- 设置：通用、深度与输出、图片、视频四组；窄屏选项使用下拉和换行布局，说明区保留参数的作用与限制。页面避让系统栏和键盘，阅读宽度限制为 840dp。
- 任务：只读现有图片/视频任务、来源、进度和错误。打开任务面板不新增任务、不全局恢复暂停项。
- 权限/新手/确认：先解释媒体用途再由用户请求授权，拒绝时可去系统设置；返回 App 后只在授权状态变化时刷新。删除、重生成、替换原图分别说明范围；保存副本和替换原图不混为一谈。打开普通图片仍沿用原逻辑自动开启 VR，指南与实际行为一致。

`StudioLayout` 只计算显示列数和标题位移，不修改保存的列数偏好、生成参数、来源顺序或媒体数据。布局按可用宽度及字体缩放收敛列数，避免平板沿用过密手机格子或大字体挤出控件。

## 参考新版与 V7 的关系

本项目 `CENTERED_V7` 是手机滤波/缓存编号，不是上游的 V2.2 版本号。旧 V6 的历史非对称取样和归一化会降低深度幅度；居中 V7 不具有相同幅度。因此相同强度不保证相同轮廓或视差。本次不把 V7 换成另一个公式后继续使用原缓存键，也不声称修复了所有 V7 画质问题。

按用户本次追加要求，新增独立 `REFERENCE_V8`，参考截至 2026-10-31 的上游 main `30372fec69a1929ce6eb5fded8d23ba2604fd68f` 中 [外部深度 V2.2 节点](https://github.com/SamSeenX/ComfyUI_SSStereoscope/blob/30372fec69a1929ce6eb5fded8d23ba2604fd68f/sbs_v2_with_external_depth.py)：

1. 沿用当前稳定 TFLite 深度模型和 GPU/CPU 会话，不导入桌面 PyTorch 模型或 ComfyUI 服务。
2. 参考模式使用输入深度与请求的反转；上游该外部深度节点不使用其 blur 参数，所以此模式不套用旧 V6/V7 滤波和水平填充控件。旧设置值保留，切回旧模式仍可使用。
3. 直接由浮点深度转为参考模式规定的 8 位取样，不把诊断 PNG 读回计算。按像素中心最近邻取样，按从右向左的顺序投影，显式标记空洞。
4. Parallel 定义为左眼原图、右眼位移，匹配该上游节点；与手机旧模式的眼序定义不同。旧模式原眼序未改。
5. 位移上限为单眼宽度 × 强度 / 500。强度 5 约为图宽 1%，建议从 5 开始，不能把旧版强度直接当作同一效果。
6. 新增唯一固定依赖 OpenCV Android 4.12.0，调用 [Telea inpaint](https://docs.opencv.org/4.12.0/d7/d8b/group__photo__inpaint.html)，半径 3。原生 Mat 在 finally 释放，补洞分配串行受限，额外缓冲计入参考模式自身的解码内存估算。加载/补洞失败会报错，不静默改用别的算法。

新缓存标识为 `depthSSS22V8`，V6/V7 原键保持不变。视频队列原有模式字段可往返新值；旧队列缺字段仍按原规则恢复旧模式。深度放大仍可选，保留 `_du1_...` 的尺寸、插值、顺序隔离；参考节点、模型及移动端预处理不同，不宣称整条 ComfyUI 工作流逐像素相同或总能优于 V6。

## 保留的核心约束

来源队列、当前图优先、前后 2/4/8 与补位、各暂停原因、GenerationGuard/staging 发布、原生 GPU 线程归属、强制 GPU、单源 SBS 视频、原 PTS/音频、现有设置与持久化没有重写。对照恢复后的实际原源码，8 个核心区域经 LF 归一化后逐字相同，包括来源/队列/删除、持久队列、模型下载、GPU 会话、视频流水线、双眼手势/单源 GL 播放及原缓存版本格式。参考模式只在生成器的立体投影入口分支，不替换旧路径。

图片仍为 JPEG 100 左/右眼缓存，属于有损压缩；无损 AVIF 仍仅在导出时编码。旧 WebP/SBS、旧视频编码缓存及已有生成结果保持兼容。

## 已知边界

- 两台实际设备为 Android 17、4 KB 内存页。本次不会把 Android 17 的调试兼容提示隐藏后说成解决 16 KB；旧 TFLite 等原生库仍需单独重编译/迁移和 16 KB 设备验收。参见 [Android 官方页面](https://developer.android.com/guide/practices/page-sizes)。
- 没有声称任意设备 GPU 兼容、所有人像/视频的轮廓都更好，或操作性能全面提升。参考模式的补洞增加 CPU/原生内存开销；视差大时仍可能出现重建伪影。
- 真正的遮挡区域没有原始像素，Telea 不是生成式补画。超大图、长视频、HDR、VFR/高帧率、热降频和长时间按住拖动仍需更大样本验证。
- 普通版及旧备份仍需独立保管，本次发布不授权删除它们。
