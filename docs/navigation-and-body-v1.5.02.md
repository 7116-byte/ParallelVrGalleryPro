# v1.5.02：参数入口与人体多点位复核

图库顶栏原先按到列表顶部的绝对距离隐藏，导致必须回到最顶部才能找设置。改为随滚动方向收起/露出，底部导航增加常驻快捷设置。设置页与调试页的紧凑返回/参数栏固定，内容仍独立滚动。调试直接进入深度参数，返回保留原调试滚动位置。临时深色 Viewer 退出后恢复系统主题的状态栏图标对比度。

六模式参数、算法、队列、媒体和缓存规则不改。输入框对主节点限制为其实际支持的 0–100 UI 范围（渲染器支持 1–100；0 的历史行为未在此改写），避免允许输入大于 100 后运行报错。

## 多点位方法与结论

用户提供 V6=30、V7=25、V8/V9=4.5、V10=35、V11=6，说明在六模式临时对比中仅调强度，以胸口蝴蝶结作单点观察，并要求改为人体多点计算。本版不将这组观察直接写入默认值。

改用三张授权人像的面部、肩部、手部、衣物蝴蝶结和衣褶区域，仅匹配人体/衣物内部纹理。检查每点的有符号眼间位移，并计算人体点对之间的相对视差；不再减去远背景中位数。弱纹理或往返匹配不合格的区域标为无效，不用背景或零值补齐。

新增 21 份 Android 实际眼图，复用已采集的模型深度，不重新跑 GPU 推理。与旧候选合并前逐图验证源图哈希相同。按区域内共同有效特征的中位数、每图点对等权、三图等权比较；目标仍为原先指定的 V10/50，并保留用户各强度及 V11/35 对照。

仅看离散候选内，三张人像分别偏好的 V6 值为 100/100/30，V7 为 40/50/25，V8/V9 为 2.5/4/3，V11 为 45/55/55。这说明单图/单点与整体统计有差异，不能给出适用于所有人体点位的固定“等深公式”。三图汇总候选中 V6=100、V8/V9=3.5、V11=50 仍较接近；V7=45 与 50 的误差差只有约 0.01 px，不足以证明换默认值更优，因此保留原可编辑起点，修改界面说明，不将其称为通用视觉等效。

V10/V11 在三张图上使用同条件时，预处理浮点深度逐字节相同；V11=6 确实用 6，代码没有隐含转换到 35。新增纯投影测试验证在同一内部特征上 V10/V11=35 的位移相差小于一个像素，而 V11=6 明显更小。整数取样/位移与覆盖填充会使局部阶跃和连续位移的视觉不同；不能仅用一个点推断整图比例。

以上是离散候选与稀疏纹理匹配，不是人体真实深度、双眼舒适度或全面画质排名。输入仍固定 518；边缘伪影及不同尺寸的视差差异仍存在。私密完整逐点对报告、无效点计数、点位图、浮点数组在 `.local/iteration-1.5.02/`，不上传。

本轮平板六模式页面日志确认 30/25/4.5/4.5/35/6 均实际传入，没有把 V11 的 6 读成其他数。该页面受现有内存预算限制，实际单眼为 1063×1063；受控点位分析为单眼宽 1280，二者必须分开记录，不能作为完全同条件的对照。没有回溯证据证明用户此前手动对比也是 1063。主节点以单眼宽度计算像素位移，因此“小于 6K 就不影响”不成立；此版没有改写内存预算或各路线的历史尺度约定。

## 验收边界

本轮只操作平板。最初的自动滚动验收遇到非 QA VR 页面，立即停止；用户反馈可能误触，所有非 QA 新工作保留，不将来源断言为已确认。后续只在 61 项专属 QA 相册中执行，手势按实际横竖屏尺寸计算，不使用固定手机坐标。原设置与队列已备份，最终合并恢复记录见发布验收。
