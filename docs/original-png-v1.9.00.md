# v1.9.00：预览 JPEG 100，保存从原图重做 PNG

普通图片“保存无损 PNG”从所选结果捕获参数，重新读取原图、执行记录的深度模型和投影，直接写 PNG。旧版保存是把已损失的 JPEG 眼图拼成 PNG；本版普通保存不再走该路径，也不会复用旧 export_sbs.png。预览及视频帧缓存继续 JPEG 100，历史缓存不迁移、不删除。

## 参数、尺寸与文件发布

- 生成相册多选直接传入所选 ManagedCacheItem，不再用图片索引查询最新结果。普通图库保存也在异步开始前捕获条目、版本、GenerationGuard token 和参数，页面切换或设置变化不改变保存内容。
- 恢复记录的模型、GPU/强制项、模式、强度、滤波、填充、两项历史反转、深度放大/顺序和历史自动匹配标志。模型 ID/校验、原图身份、尺寸和参数均检查；新字段缺失仅使用明确的历史默认，缺少核心参数或损坏值会失败。
- 保持所选结果的实际单眼尺寸。例如结果记录 1280×960，导出为 2560×960 SBS。仍从原图解码到该尺寸；不会放大 JPEG 缓存，也不擅自改用当前设置或完整原图尺寸而改变视差。内存不足明确失败，不能静默缩小。
- 原图不存在、已修改或无访问权限时不使用预览替代；失败保留原图、旧结果和已有历史版本。保存是单独的显式工作，不创建来源队列/邻图预加载，不修改设置。
- 暂存位于扫描范围外 export_work。PNG 完整后复制到本次新建 MediaStore pending 行，最终发布仍在 GenerationGuard 锁内检查 token、版本和创建时间。删除、替换或取消使本次发布失败，清理自己的 pending 行和暂存。

旧 AVIF 设置值及文件保留作兼容；普通图片保存固定为明确的 PNG。视频保存仍复制已经生成的 MP4，不能称为从原视频无损重建。

## 单眼复用与 PNG 写入

六种模式本来就只投影一只眼：V6/V7/V10/V11 改左眼，V8/V9 改右眼。保存时直接引用解码后的原图作为另一眼，保持各模式原眼序。SbsPngWriter 逐行读取两眼，直接写标准 sRGB、8-bit RGBA PNG，采用可逆 Sub filter 和低压缩 zlib 流；不额外创建整幅 SBS 位图，不经过 JPEG。

“无损”指直接生成的 8-bit 像素不会再经有损压缩，不表示投影没有遮挡/补洞误差，也不恢复源 JPEG 已有损失。现有生成管线不是 HDR/16-bit 无损工作流。

## 本次验证

- 153 项 JVM、25 类：新增所选版本与原图身份、六模式参数、770 模型、分数强度、深度放大顺序、历史默认/损坏拒绝，以及独立 PNG 解码器全 RGBA 像素、CRC/分块、取消和写入失败传播。
- 平板非 debuggable benchmark、原证书、原尺寸/字体，始终停留桌面；不启动真实 Activity/ViewModel/图库队列。只读授权测试副本，模型和缓存通过 ContextWrapper 全部限制在专属目录。
- P3 六模式的 JPEG 左右眼和旧导出文件被故意写坏，保存仍成功；PNG 与原图经相同参数直接生成的、编码前 SBS 逐像素一致，未投影眼与原图解码像素相同。参数文件及被写坏的测试缓存保持原样，证明没有偷偷更新预览。
- 补测 P1/P2/官方裁片，以及 P3 的真实 770；原图眼均逐像素一致，实际记录到 770 推理。原图缺失、损坏参数与中途取消拒绝生成/发布；新建 QA 图库 PNG 字节相同并只删除自己的 URI，发布失效测试通过。
- 六模式小样本从已有 518/GPU 模型开始的原图渲染并写 PNG 约 0.39–0.47 秒，不含图库复制、完全冷模型及 App UI。不是所有尺寸/设备的速度保证。

视频逐帧解码、一次 GPU 深度推理、单眼 CPU 投影/补洞后，由 OpenGL 双纹理直接画到 MediaCodec Surface，输出 H.264 MP4，复制音频并保留 PTS；原先也没有给双眼各跑一次模型。额外复用只能减少原图眼的位图复制/短时内存，不会省掉主要的深度推理。

终版 A4/B4 的 48 帧全部未命中结果缓存；B4 实际共享 48 帧，A4 为 0。总耗时 12.735→12.706 秒，仅约 0.2%，属于测量波动，没有证明显著提速。96 份 JPEG 眼图与 MP4 全部解码像素一致，48 个 PTS 和音频包哈希保持。720p 每帧少分配一份约 3.5 MiB 的原图眼位图；不代表常驻内存减少 48 倍，也不会省去整幅 SBS 的 H.264 编码。详见 [验收记录](releases/v1.9.00.md)。初测 A1/B1、A2/B2、A3/B3 未实际共享，不用于收益结论；其中原解码器在 sequential MediaCodec 与 retriever 间按成本选择，两条路径不能交叉宣称字节相同。

本地原始证据 `.local/iteration-1.9.00/` 保持私密。构建通过、生成验证、UI/设备范围和公开下载分别记录。

Android retriever 返回的帧实测像素全不透明，但 Bitmap.hasAlpha 标记为 true，初版条件因此没有触发共享。终版仅对 sRGB ARGB8 视频帧直接复用；其他配置保留原复制路径。另对 retriever 原始帧执行六模式前后逐像素比较、原帧存活到消费者完成及最终回收检查，全部通过。流水线共享原帧后，所有权移交到双眼结果，必须等编码和缓存写入两个消费者都结束才释放；首帧和缩放分支也分别处理，不能提前 recycle。
