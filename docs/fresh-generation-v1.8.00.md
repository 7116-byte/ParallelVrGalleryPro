# v1.8.00：新图片、新视频的实际生成速度

这次只评价未生成过的任务，不把成品缓存恢复计入收益。保留模型权重、原精度选项、模型输入、输出尺寸、视频帧率/码率、原始 PTS、音频及 JPEG 100。未升级 Android 依赖。

## 测量条件

单台原生平板，既有授权的三张人像与官方预览裁片；另生成 2 秒、1280×720、24 fps、48 帧并带音频的合成片。图片/视频使用稳定 518、GPU、V10/50，与本次平板保存的 GPU 配置相同。每次进入全新的私密缓存根目录；每片 48 帧全部 cacheHit=false，逐帧推理计时记录也为 48 次。没有启动图库/队列或读取其他媒体。

早期 Debug 数据只用来定位；正式前后比较采用非 debuggable 的 benchmark 构建，继承 Release 配置，统一对本包执行 AOT speed 编译。基线为 `e51c8b9` 的 v1.7.00 生产源码，只加入同样的计时器/QA 入口。模型已就绪与完全未初始化分开测量。测试 APK 含显式 QA instrumentation，仅作本地测量；正式 Release 不含它。

## 实际结果

基线新视频重复两次为 17.759 / 17.785 秒，中位数 17.772 秒；终版确认结果如下。单设备小样本不能外推为所有机型与尺寸的保证。

| 新任务场景 | v1.7.00 | v1.8.00 | 说明 |
| --- | ---: | ---: | --- |
| 新视频，同配置图片模型已就绪 | 17.772 s | 12.664 s | 约快 28.7%，仍实际推理全部 48 帧 |
| 新视频，模型完全未初始化 | 18.063 s | 17.421 s | 约快 3.6%，冷建模仍明显 |
| 新人像 P2，模型已就绪 | 392 ms | 363 ms | 960×1280 不变 |
| 新人像 P3，模型已就绪 | 413 ms | 360 ms | 1280×1280 不变 |
| 新示例裁片，模型已就绪 | 358 ms | 344 ms | 560×836 不变 |
| 首图 P1，含模型创建 | 4.668 s | 4.541 s | 1497×1497 不变；初始化波动较大，不宣称明显提升 |

“图片模型已就绪”可以来自原有启动准备或此前的图片任务，不能称为完全冷模型。之前定型方案的独立复测约 12.703 / 12.735 秒，终版对相同配置的共享路径仍稳定；增加了不同模型资源保留保护后得到 12.664 秒。完全冷模型的 3.6% 必须与 28.7% 同时报告。

图片选择 770、视频使用 518 时配置不同，不能套用 28.7% 的共享收益。本轮平板收尾保存的图片配置就是 770，保持不动；不能为了复用会话自动降到 518。未保留额外闲置视频模型来换取后续速度，避免增加常驻内存后压低图片的自适应输出尺寸。

## 瓶颈与改动

非调试构建的视频稳态阶段中位数，单位 ms：

| 阶段 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 缩放/读像素 | 3.44 | 3.33 |
| RGB 浮点打包 | 9.10 | 1.98 |
| TFLite GPU 调用 | 243.04 | 242.71 |
| 输出读取/归一化 | 13.42 | 4.41 |

GPU 算子仍是主要瓶颈。本版减少输入输出开销，未声称 GPU 数学计算本身快了 28.7%。流水线持续帧间隔约从 269 ms 到 253 ms，总耗时的额外收益主要来自不重复创建已就绪的模型会话。

完整流水线也逐帧计时：模型已就绪的基线两次解码中位数为 50/57 ms，终版 50 ms；深度阶段 269→253 ms，深度后处理约 11 ms，SBS 投影 29/30→24 ms，编码约 13 ms，缓存写入 10→14 ms。阶段有界并行，不能把这些数相加当作单帧延迟。持续帧间隔随深度阶段变化，编码和写盘当前没有控制整体吞吐，因此本版优先减少实际推理前后的开销，未凭更换格式就宣称视频加速。

- `TensorTransfer` 将逐浮点 ByteBuffer 访问改为 FloatBuffer 批量访问。输入使用同样的 `/255f` 查表和 RGB 顺序，输出继续相同的有限值处理、min/max 与 FP32 归一化。测试核对全部 256 个通道值、字节序、NaN/Inf/负零、常量、518/770 及重复写入，逐位一致。
- 输入只保留一行临时数组（518 时约 6 KB），分块写入。整图约 3.2 MB 的早期原型曾使内存限幅尺寸从 1497 降至 1488，已拒绝；最终八份图片眼图尺寸和文件字节均与基线一致。原有内存安全策略保持。
- V10 保持相同量化、位移、裁切、填充与最后写入者规则，反向遍历并跳过已确定的目标像素，每个目标只写一次。非调试独立测试 1280 方图约 33→16 ms、2560 方图约 128→64 ms，所有像素相同；随机、边界、非有限深度回归通过。V6/V7/V8/V9/V11 投影不改，缓存键不改。
- 新视频借用已经存在且完整配置相同的图片会话，省去重复的模型校验/创建/准备。键包含模型、线程数、GPU、GPU 模式及强制 GPU；没有现成匹配会话时仍独立创建并释放视频会话，不淘汰已准备的其他图片模型，特别是 770。CPU 额外 worker 仍独立，GPU 仍原拥有者线程、当前图仍最高优先。
- ViewModel 清理先等待视频 worker，再关闭共享池；借用计数保证图片结束或池关闭请求不会提前释放视频使用中的原生资源。新增关闭顺序、配置隔离、不同模型保留测试。

批量访问语义见 [Android FloatBuffer](https://developer.android.com/reference/java/nio/FloatBuffer)。GPU 同步与后端限制见 [TFLite GPU 文档](https://android.googlesource.com/platform/external/tensorflow/+/upstream-master/tensorflow/lite/g3doc/performance/gpu.md)。本版没有修改图或训练权重。

## 未采用的路径与精度证据

准确 OpenGL 后端在此平板缺少模型所需 const shader，强制 GPU 失败，未回退 CPU。默认和显式 OpenCL 的原精度调用都约 240 ms。另测完整精度的 FAST_SINGLE_ANSWER，对四张图约 265–268 ms，现有 SUSTAINED_SPEED 约 242–246 ms，因此保留原设置。没有通过降低精度或尺寸换速度。

终版与基线的 8 份图片眼图、96 份视频眼图的尺寸及 JPEG 字节完全相同。五份实际 MP4 完整解码，均为 2560×720、48 帧；逐帧 PTS 与复制的音频包哈希保持。原文件、历史结果、模式参数和队列不重算或迁移。145 项 JVM 测试通过，构建、签名、设备与发布证据见 [验收记录](releases/v1.8.00.md)。

本轮仅对 518 作性能比较，770 只作数据传输契约回归；不声称 770 有同幅度提速。GPU 内核和完全冷建模仍需更深入工作；历史任意视频缓存缺口的平滑状态问题仍保留，没有用缓存恢复来证明本轮新视频更快。私人原始证据位于 `.local/iteration-1.8.00/`。
