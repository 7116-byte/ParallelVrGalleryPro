# v1.15.01 · 视频生成诊断与取帧优化

「设置 → 通用 → 应用更新」增加 GitHub 项目入口。

## 视频深度尺寸

旧版每帧按当时的可用堆内存重算单眼工作尺寸。V10 和 V11 会把模型深度映射到这帧的单眼工作尺寸再平滑，因此即使关闭额外深度放大，调试页的后处理尺寸也可能跳动。新版在生成任务中固定工作长边上限，分段续跑沿用已记录的上限。原视频帧本身改变分辨率时，实际尺寸仍如实显示。

调试页分别显示模型原生深度、恢复到视频朝向的有效深度、后处理深度和 SBS 成品尺寸。新任务清除上一轮读数，并兼容读取历史缓存。并发内存预算纳入未缩放解码帧，资源不足时保留已提交的分段供续跑。

## 取帧与流水线

调试页区分 MediaCodec 和兼容取帧，列出取帧、YUV 转换、解码检查及缓存读取。首帧和每个分段的首帧也记录取帧时间。剩余耗时是估算，包含排队、初始化和未单列的工作。帧流水线各阶段会并行，整段耗时计算包含分段交接和最终合并。

连续解码优先送入当前可用的压缩样本，等输入缓冲忙时再等待输出。YUV 按行批量读取，共用相邻像素的色度系数，使用有界的 ARGB 缓冲。色彩、裁切、旋转继续使用相同计算，核对原始帧时间戳。兼容路径使用 Android 取帧器，模型分辨率、推理精度和成品编码按任务配置执行。

## 验证

本地签名 Release 和 GitHub Actions 均通过 240 项 JVM 测试，Lint 0 错误。新增覆盖大分辨率内存波动下的工作尺寸、历史分段兼容，以及 YUV 裁切、步长和交错色度的逐像素比较。包名为 `com.local.parallelvrgallerypro`，版本为 `1.15.01 / 11501`，使用原发布证书。[GitHub Actions](https://github.com/7116-byte/ParallelVrGalleryPro/actions/runs/45191045440)

### 平板同素材对照

两版使用同一授权原片的前 96 帧、相同任务参数和空生成缓存。各提交两段 45 帧，并进入第三段。运行日志确认两版均用 QNN GPU FP16（378×672），关闭 CPU 回退。取帧统计使用 93 个非段首帧，出帧间隔使用同段内样本。

| 指标 | v1.15.00 | v1.15.01 |
| --- | ---: | ---: |
| 取帧中位数 / P95 | 121 / 134 ms | 29 / 56 ms |
| 深度推理中位数 | 97 ms | 94 ms |
| 同段内出帧间隔中位数 / P95 | 125 / 232 ms | 117 / 179 ms |
| 冷启动至第 96 帧 | 21.10 s | 18.95 s |
| 后处理深度 | 73 种实际尺寸 | 96 帧均为 1080×1920 |

这组数据覆盖起始片段和两次分段交接，完整长片耗时、后段热负载和最终音频封装仍需另测。新版首帧冷启动为 7.20 秒，旧版为 6.55 秒，其中 QNN 准备分别约为 6.08 和 5.41 秒。结果证明该片取帧和本次样本总用时改善，首帧提速仍待优化。
