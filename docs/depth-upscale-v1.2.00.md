# v1.2.00: 生成页操作与可选深度重采样

## 管理操作

生成图片相册首页长按多选后，增加重新生成和全选。重新生成先确认数量，按当前设置处理所选相册中的原图，不同版本包含同一原图时仅排一次。该语义与原先相册内的当前设置重新生成一致，不表示重放每个相册的历史参数。

重新生成只清理当前目标参数版本，不再删除该原图的其他参数版本；生成失败会报告错误，不承诺恢复被明确重做的目标版本。系统原图不删除。任务继续通过原 `GENERATED` 手动入口和删除 token 保护，不修改页面预加载边界。

相册内全选只选当前版本图片，视频页全选只选当前生成视频列表，首页全选只选当前生成相册。后台出现的新结果不自动追加到已经选中的集合，需再次点击全选。列表移除的项从选择中剔除。操作栏采用现有 Material 图标、48dp 触控区、语义名称和提示框，在原顶栏行内替换设置/刷新，不新增一排文字按钮。

## 深度处理顺序

模型输入/输出仍为 518×518，不改推理会话、GPU 设置或模型文件。

默认关闭：继续调用原 `DepthFilters`，按现有整数坐标映射投影；两种边缘模式的输出和缓存名称保持兼容。

开启后的默认顺序：

1. 原有深度推理；视频先执行原有时序平滑。
2. 在模型分辨率执行所选旧/新版滤波与深度反转。
3. 重采样为目标尺寸的浮点深度。
4. 按新深度宽高投影，不再硬编码 518。

可切换先放大再平滑：第 2、3 步交换，窗口以放大后深度像素计。同一个 3×3 窗口对应的图像范围会不同；两个顺序不承诺视觉等价。默认先平滑是为保留原窗口尺度并减少滤波计算，并非保证所有人物边缘都最佳。

## 尺寸与插值

- 原图尺寸：以实际解码/处理的图片或视频帧为准，仍受现有输出长边限制。不会把已被解码降采样的图虚构回高分辨率。
- 自定长边：256-8192 像素，保留源宽高比，且不超过实际处理图尺寸。
- 内存限制：按进程最大堆的八分之一、最多 96MiB 分配深度工作预算，并按每像素 16 字节估算滤波/预览等峰值，必要时进一步缩小。不是模型显存比例设置，也不是绝不 OOM 的保证。
- 最近邻、双线性、Catmull-Rom 双三次均直接处理 FloatArray。横纵可分离重采样，端点对齐与原投影坐标保持一致，边界复制。双三次过冲限制到 [0,1]，避免非法视差。
- `depth.png` 仍是 8 位诊断预览，但立体投影用浮点深度，未把 PNG 读回作为计算输入。
- 放大不能恢复模型没有推断出的真实细节；可能增加内存、后处理及深度 PNG 写入时间，尤其是视频逐帧处理。

概念参考：[OpenCV 几何变换与插值](https://docs.opencv.org/4.x/da/d54/group__imgproc__transform.html)、[均值滤波](https://docs.opencv.org/4.x/d4/d13/tutorial_py_filtering.html)。本实现扩展现有浮点深度流程，没有引入 OpenCV 原生库；端点对齐和三次核的具体选择以代码及数值测试为准，不宣称与 OpenCV resize 逐像素相同。

## 缓存和诊断

开启后缓存名称追加紧凑的 `_du1_m..._i..._o...`，区分长边、插值和顺序；关闭时不追加后缀。图片与视频共享设置，但继续各自的缓存格式。修改参数不自动重做已有成品。

视频队列编解码抽为可测试的 `VideoQueueCodec.kt`，新字段追加到原格式末尾。旧队列缺少新字段时保持关闭，旧边缘模式恢复规则不变。不同深度设置的中间帧不会互相命中；视频时间线、编码和单播放器路径不变。

图片 `params.json` 用结构化 JSON 写入实际深度宽高和设置，支持名称中的转义字符。视频运行诊断显示当前新生成帧的深度尺寸，尺寸变化时记日志；缓存命中帧没有新后处理尺寸时不伪造数字。视频完成元数据保存设置。

1. 竖屏/横屏首页选择多个相册，重新生成确认数量正确，取消无任务，确认不新增邻图预加载。
2. 进入具体相册全选，不选其他相册；切视频页全选只选当前视频列表。检查长按拖选仍正常。
3. 同一图片分别关闭、双线性、双三次，检查左右眼尺寸/方向和轮廓，调试参数中的实际深度尺寸符合上限。
4. 两种顺序搭配旧版/新版滤波、0/1 关闭窗口，检查差异和生成耗时。
5. 大图内存限制、开启放大的视频暂停/续跑、切换设置后新旧缓存隔离、SBS 播放与同步缩放。
